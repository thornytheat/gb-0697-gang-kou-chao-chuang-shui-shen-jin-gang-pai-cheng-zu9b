# 潮窗字段

id保持字符串。kind取tide、ship、pilot、block。start/end带时区；统一UTC秒。tide的value为潮高；ship为吃水；m/cm统一为m。ship的aux为通航分钟。version为递增版本，采用同ID最高版；同版多条隔离。潮位乱序按时间排序。

基准水深8m，安全余量1m，要求潮高>=吃水+1-8。相邻潮位最长允许3小时插值；缺口不外推。航道区间为半开，结束同刻可开始下一航次。引航窗口须覆盖整个航次。排程按最早申请时间、船舶ID确定先后，采用最早可行窗。并非全局最优调度。

业务ID按kind命名空间隔离。同一UTC时刻的潮位不同值全部隔离为TIDE_TIME_CONFLICT，不能用其中任意值开启安全窗；同值重复仅保留编号最小者。

冲突潮位时刻保留为插值断点，相邻有效观测不能跨越该时刻推算安全窗。


## 待定区与发布

- 船舶申请解析失败（数值缺失、单位无效、时间无效等）不得静默丢弃：连同原因码、原申请行、来源行号进入 `pending`，且该船整船不参与排程；若失败版本比现有有效版本新，也不得回退使用旧版本。
- 只有数据有效但无安全窗的船保持 `NO_SAFE_SLOT`，去向为“无安全窗”，与“未核实”分开显示。
- 发布（publish）冻结当次所有已排船位的开始/结束 UTC 秒。之后的补正只对待定区船舶生效，新船只能绕开已冻结船位寻找窗口，已发布船位时刻不变。
- 每条补正记录轮次、提交行、前后状态差异与冻结船位清单；重复提交同一内容不新增轮次。
- 同一规则版本 + 同一输入文本只对应一个批次；补正后的文本再次提交仍归原批次，不重复占道。
